# Portfolio Design System

This file is the highest-priority design reference for the portfolio website. Future visual decisions must preserve the verified project content, research boundaries, URLs, and information architecture.

## 1. Positioning

The portfolio represents:

**Project Management × Data Analytics × Business Intelligence**

It should communicate a professional who combines business context, analytical methods, and project execution. It is not a pure data-science, machine-learning-engineering, or visual-design portfolio.

## 2. Design Character

The intended character is:

- Professional
- Analytical
- Modern
- Editorial, used with restraint
- Credible and easy to scan

Editorial influence should appear through typography, grid, spacing, and evidence-led storytelling—not oversized headlines, art direction, or magazine-style composition.

## 3. Core Principle

**Content > UI**

The work, evidence, research boundaries, and real outcomes must remain more important than interface decoration. The main design sources are:

1. Typography hierarchy
2. Clear and adaptable grids
3. Real project visuals
4. Restrained neutral color with one blue accent
5. Evidence-led content

## 4. Information Hierarchy

- Project titles, business questions, evidence, findings, and limitations take priority.
- Section headings support navigation; they must not behave like a second hero.
- Sections do not need to use the same layout, metadata pattern, or visual rhythm.
- Repetition is acceptable only when it improves scanning or comparison.
- Conceptual slogans must not outrank actual experience or project evidence.

## 5. Typography

- Use a stable system sans-serif stack.
- Maintain a clear H1 > H2 > H3 > body > metadata hierarchy.
- Hero typography may be distinctive but controlled.
- Avoid oversized section headlines and forced editorial line breaks.
- Body text should remain readable at 16px or above where practical.
- General-reading metadata should be approximately 12px or larger.
- Uppercase labels are supporting navigation, not primary content.

## 6. Grid and Layout

- Use grids to clarify relationships, not to make every section look identical.
- Preserve consistent container alignment while allowing sections to use different internal structures.
- Prefer natural content flow over rigid three-column frameworks.
- Responsive layouts must prioritize readability over preserving desktop column counts.
- Avoid large empty areas that delay access to projects or evidence.
- Do not change the established website information architecture without explicit approval.

## 7. Project Visuals

**Real project visuals > UI decoration**

- Use verified screenshots, presentation visuals, research figures, or clearly identified project covers.
- Project visuals should be visually prominent and appear early in case studies.
- Never fabricate dashboards, charts, KPIs, rankings, client results, or product functionality.
- A typographic project cover must be presented as a cover, not as a dashboard screenshot.
- Decorative UI must never compete with the work itself.

## 8. Color

- Base: neutral light background and near-black text.
- Accent: one restrained blue family.
- Use color primarily for hierarchy, links, focus, and evidence emphasis.
- Avoid unnecessary gradients, neon colors, purple AI palettes, and multi-accent systems.
- Maintain accessible text contrast.

## 9. Components and Effects

Avoid:

- Excessive cards
- Card-within-card or nested dashboard widgets
- Excessive pills, badges, or chips
- Decorative icons without functional meaning
- Excessive rounded rectangles
- Heavy or layered shadows
- Gradients and glassmorphism
- Decorative animation
- Repeated UI patterns used only for visual consistency

When cards are appropriate, keep borders, radius, shadow, and hover treatment restrained.

## 10. Anti-Patterns

The portfolio must not resemble:

- A SaaS landing page
- An AI startup website
- A generic AI-generated portfolio template
- A designer or art-direction portfolio
- A cyberpunk or futuristic interface
- A dashboard made from decorative widgets

## 11. Project Management

Project Management content follows this priority:

1. Actual experience
2. Actual working methods
3. Evidence
4. Measurable outcome

Actual experience must remain more prominent than conceptual frameworks. Do not add abstract process models such as Identify / Improve / Deliver unless a verified project explicitly requires them. Preserve the documented approximately 35% reduction in operational error rate without broadening its meaning.

## 12. Responsive Standard

Validate at 375px, 768px, 1024px, and 1440px.

- No horizontal overflow
- No uncontrolled heading scale
- No dense two-column card layouts when readability suffers
- Project visuals remain recognizable
- Navigation remains usable
- Mobile users reach selected work without excessive introductory content

## 13. Change Discipline

Use this order for future design work:

1. **Distill** — remove duplication and non-essential UI
2. **Typeset** — correct hierarchy, size, measure, and readability
3. **Layout** — adjust grids, alignment, and responsive behavior
4. **Polish** — refine borders, shadows, hover states, and spacing

Do not add a component when deletion, clearer typography, or better content order solves the problem.
